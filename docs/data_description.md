# وصف البيانات

البيانات في `data/dataset.csv` ليست من متجر حقيقي، بل من **محاكاة** تنشئها الدالة `simulate_experiment()` (في `src/simulate_data.py`، وهي نفسها في القسم 5 من الدفتر) ببذرة عشوائية ثابتة **2026**، فتتكرر النتائج نفسها في كل تشغيل. تفترض المحاكاة أن **5,000 مستخدم جديد** يدخلون التجربة كل يوم لمدة **7 أيام** (35,000 مستخدم)، ويُوزَّع كل مستخدم عشوائيًا على النسخة A أو B بنسبة 50% لكل منهما. نسبة الطلب الأساسية **10%**، وتختلف من مستخدم لآخر حسب نشاطه (نشاط مخفي لا نقيسه مباشرة، لكنه يظهر في طلباته السابقة). الأثر الحقيقي المخفي للنسخة B هو **0.8 نقطة مئوية**، واخترناه عمدًا **أقل من أصغر أثر يغير القرار (نقطة واحدة)**، لنختبر هل يصل التحليل إلى قرار صحيح عندما يكون الأثر الحقيقي صغيرًا. ولا يوجد في المحاكاة **أثر حداثة** (الأثر ثابت كل الأيام)، ولا **خلل في التوزيع (SRM)**. قيمة الطلب حوالي 120 ريالًا في المتوسط (انحراف معياري 50، وحدّ أدنى 10)، وهامش الربح 25%، ونسبة الإلغاء 5% ونسبة التواصل مع الدعم 3%، وكلها بلا فرق بين النسختين.

| العمود | معناه |
|---|---|
| `user_id` | رقم المستخدم (من 1 إلى عدد المستخدمين)، ولا يتكرر |
| `variant` | النسخة: `A` التقييمات أسفل الصفحة (الحالية)، و`B` التقييمات أعلى الصفحة |
| `day` | يوم دخول المستخدم إلى التجربة (من 1 إلى 7) |
| `pre_orders_90d` | عدد طلبات المستخدم في آخر 90 يومًا قبل التجربة (نستخدمه في CUPED) |
| `ordered` | هل أتم المستخدم طلبًا خلال التجربة (1 نعم، 0 لا)، وهو المقياس الرئيسي |
| `order_value` | قيمة الطلب بالريال، وفارغة عمدًا لمن لم يطلب |
| `revenue` | الإيراد من المستخدم (قيمة الطلب، أو 0 إذا لم يطلب) |
| `profit` | الربح من المستخدم (25% من قيمة الطلب، أو 0 إذا لم يطلب) |
| `cancelled` | هل أُلغي الطلب (1 نعم، 0 لا)، وفارغة عمدًا لمن لم يطلب |
| `contacted_support` | هل تواصل المستخدم مع الدعم (1 نعم، 0 لا) |
